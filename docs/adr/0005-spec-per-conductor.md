# A net names one spec per conductor, and a conductor is addressed but never stored

The RAMMP team's demo feedback on 2026-09-30 said a harness built from the BOM had two red 8 AWG wires on the 48 V feed, one of them the return, and that nobody on the floor could build it. A net named one spec and a count, so every conductor came out the same colour. Now a net or a domain may list `conductor_specs`, one wire or cable spec per conductor, and the count is the list's length. The single `spec` plus `conductors` form stays for the common case where every conductor is the same thing, which is every cable net and most signal nets. Resolution stays net, then domain: the net's list, else its single spec and count, else the domain's list, else the domain's single spec and count. A net that overrides only the count takes the domain's list up to that count, so a two-wire brushed motor on the motor phase domain gets the first two phase colours rather than three of nothing. A cable spec may list `conductor_colors`, one per conductor, so the canvas can tell a Cat6 net's pairs apart. The BOM cut list already emitted one wire row per conductor; each row now carries the spec, part number and colour of the conductor it is, and a net's rows stay together in conductor order. A conductor is addressed as `<net id>#<index>` for selection and highlighting, derived from the list and never written to a file, so nothing new lands in the project folder. Issue #20 holds the user stories.

## Considered options

- A separate net per conductor, so the return is its own net. Rejected in the #17 grill: it doubles the net count for no harness information, and every route, splice and DRC would have to be taught that two nets travel together.
- Colour as a property of the net rather than of the spec. Rejected: the colour of a wire is a property of the wire you buy, and the BOM has to name the part. A net choosing a spec per conductor gets the colour and the part number in one move.
- A stored conductor record with its own id. Rejected: there is nothing to say about a conductor beyond its spec and its position in the list, and an id would have to be kept in step with every edit of the list.
- Making `conductors` required to agree with the list length. Rejected: a file written by hand with both set and disagreeing is a design rule error rather than a load failure, so the project still opens and the panel points at the net.
