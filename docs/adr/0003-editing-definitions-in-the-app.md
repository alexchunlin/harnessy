# The app edits component definitions by shadowing them into the project, and the connector drawer changes types in bulk

A component definition in the library names each connector's type, and nothing on the connectivity canvas said so or offered to change it. Two places now do. The inspector edits one definition: connectors can be added, renamed, retyped and removed there, on a one-off component or on a library definition. The connector drawer edits types across the project: one row per connector of every definition in use and every inline connector of a one-off, grouped by owner, filterable by type, with checkbox rows and one control that sets the type of the selection. The drawer's type filter lists every type in the library with a usage count, zero included, so it doubles as the inventory. Mating part, pin count and strain relief belong to the connector type and stay out of both editors; the library skill writes them.

The file API writes only inside the folder you opened, and the repo catalogue is read-only over it, so an edit to a shared definition copies the entry to `<project>/library/components/<id>.json` first and the copy shadows the shared one. That copy is the only thing the edit touches, so two projects that use the same definition never surprise each other, and giving the copy back restores the shared entry. A project therefore carries the repo library it was opened against, not just the merged result, because a revert has to know what it falls back to.

A type edit on a definition reaches every component that shares it. That is the point of a definition, so the drawer never detaches a component as a side effect. A component that must differ from its definition takes its own copy of the connectors from the inspector, deliberately, and stops following the definition. A one-off can publish its connectors as a definition other components then share. The harness side follows on its own: the mating part and the BOM derive from the type, and pin assignments stay as they were. A new type with fewer pins leaves the design rule check of ADR 0008 reporting the out-of-range pins until someone moves them. Nothing is dropped silently.

A designator is the only name a connector has, so a rename carries the wiring with it: net addresses, topology endpoints, the drawn pin order, and the hand-placed bends on a star net's spokes. It commits on blur rather than on each keystroke, since a half-typed name can collide with a real one. Removing a connector detaches the nets that used it across every component that shares the definition, drops any net left under two connectors, and takes the topology endpoints and their segments too. That goes further than ADR 0002, which tolerates a dangling designator in a hand-edited file; the tolerance is for loading what someone else wrote, not for what the app itself does to a project while you watch.

The drawer offers only types the library has. A type you cannot find is a job for the library skill, and the picker says so rather than taking free text. The decision was made on the ticket [Where is a connector's type chosen, and how do many change at once?](https://github.com/alexchunlin/harnessy/issues/35). The branch `build/definition-editing` holds a first cut of the inspector half; it is a reference, and the work is rebuilt on main.

## Considered options

- Writing the shared catalogue from the app. Rejected: one project would be editing the parts every other project reads, and the file API would need a second writable root.
- A drawer row per connector per component, where editing one detaches that component. Rejected: a bulk edit should reach every instance, and a detach should be a choice, not a side effect of a table cell.
- Editing the mating part and pin count in the drawer. Rejected: those are the connector type's fields, and the map rules out hand-editing library specs.
- Dropping pins that fall outside a new type's count. Rejected: the check already reports them, and a silent drop loses work.
- Leaving nets dangling when a designator goes, for the design rule check to list. Rejected: one edit to a definition would break every component using it at once, and deleting a component already detaches its nets.
- A separate dialog for the library instead of the inspector. Rejected: the inspector already shows the selected component's connectors, and the ask was to edit them where the diagram is.
- Always detaching the component being edited. Rejected: one edit reaching every instance is the reason definitions exist.
