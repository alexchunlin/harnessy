# A conductor lands on one numbered pin at each connector of its net, stored on the net

The first map deferred pin assignment because the BOM it aimed at was a cut list, and a cut list needs lengths, not cavities. This map's destination is a harness that plugs into the robot and works, and at the bench the cavity is the difference. A pin is a number from one to the connector type's pin count. Names are not part of the identity: the repo library's types carry only a count, and naming is an authoring concern that belongs to the library skill. The assignment lives on the net, as a map from connector address to an array with one entry per conductor in conductor order, null where nothing is assigned yet. The conductor is already addressed by its net and its number, so the array index is the conductor and nothing new is named. A cable net's cores take pins the same way, one per conductor in the spec's order. A purchased assembly with a moulded pinout carries no pins. Splices have no cavities and bridges are the device's business, so neither carries pins. Pins are set in the net inspector, on the connector rows, with one small field per conductor. The canvas draws connectors, not pins. Two conductors on one pin of one connector, counted across every net that connector terminates, is an error, as is a pin above the type's count. A conductor with no pin is a silenceable warning, so a project drawn before anyone has chosen cavities still exports and the build sheet prints a blank. The cut list gains a from-pin and a to-pin column. Wire rows fill them; the cable row leaves them blank and lists its pairs in its notes. One conductor on one pin only: doubling up for current is wire sizing, and two conductors on a net already model it. The decision was made on the ticket [How does a conductor get a pin?](https://github.com/alexchunlin/harnessy/issues/34).

## Considered options

- Pins named by the connector type, with the net picking a name. Rejected: no type in the library lists names, and a name on top of a number can arrive later without changing the identity.
- Each entry in a net's connector list becoming an object with the address and its pins. Rejected: every saved nets file would change shape, for the same information a sibling map holds.
- Assignment stored on the component's connector, mapping pins to nets. Rejected: a connector in no net has nothing to map, and the conductor is the thing being placed.
- A missing pin as an error. Rejected: the BOM was usable before pins existed and early designs need it to stay so.
- A pinout on the cable spec. Rejected: a loose cable's cores are placed like wires, and a lead with a fixed pinout is an assembly.
- A pin badge or pin row on the connectivity canvas. Rejected: nothing on the canvas reads a cavity, and the inspector is one place.
