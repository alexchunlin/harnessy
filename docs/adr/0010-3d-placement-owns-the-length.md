# A placed harness takes its lengths from its 3D placement, and the placement is saved per topology

The 3D Harness view came in through PR #26 with everything in memory: positions, connector rotations, tie points made in 3D and the reference model vanished on reload, and lengths reached the project only through a write button. Alex chose "3D owns the length" in that prototype, and this records it. An endpoint is placed once someone has dragged it, its harness, or arranged it in 3D; the sketch that stands the topology drawing up in 3D is never saved, so opening the view changes nothing in the project. A segment is placed when both its endpoints are, and a tie point when it has a saved position on a placed segment. A placed segment's length is derived from the curve the 3D view draws, with the strain relief stub counted, the way a route and a harness are derived. The stored `length_mm` stays the hand-typed value and counts only while the segment is unplaced, which is what a robot with no CAD uses. A placed tie point's position owns its distance the same way: the curve passes through it and the distance from its named end is measured along the curve, while the stored `distance_mm` serves an unplaced tie point. The inspector shows a derived length or distance read-only, marked as from 3D. The BOM and the slack maths of ADR 0006 read one core function that prefers placement over the typed value, and the bend radius check of ADR 0007 reads the same placement. There is no write button, so a drag is one ordinary undo step and the prototype's unwritten tie points go; double-clicking a tube makes a real tie point with its position in the same edit.

The 3D view opens with lengths locked, and the lock is a browser preference. Locked, dragging or turning any part moves its whole connected harness as one rigid body, so no length or distance changes. Unlocked, called Stretch in the panel, dragging one part moves only that part and the segments at it stretch. Alex asked for the lock so a harness can be moved into place without changing the whole assembly by accident.

The placement lives in `canvas/<top>.3d.json`, one per topology, in integer millimetres: a position per placed endpoint, a rotation in degrees per placed connector, and a position per placed tie point. Nothing else goes in it, not the camera and not the sketch. Only connectors turn; a breakout, splice, point and tie point save a position only, and the strain relief stub leaves a connector along its saved rotation at the connector type's declared length. Positions belong to endpoints: removing an endpoint in the topology view removes its position in the same edit, removing a segment removes its tie points and their positions, and re-ending a segment touches nothing in the file. ADR 0001 reads canvas files as drawings that never change the model. This file changes lengths and feeds a design rule, and it still sits under `canvas/` because it is a drawing the user makes, so this ADR records the exception. A "Clear placement" action in the 3D panel removes every position and rotation of the shown harness as one undoable edit, and the harness falls back to its typed numbers and the sketch.

The reference CAD model is a project thing, since the machine is the same for every topology. Its entry sits in `canvas/reference.json` beside the photo list of ADR 0009, as one `model` field with a path relative to the project, its units, a position and a rotation in degrees. The file is copied into `reference/` through the upload route the photos use and read back through the bytes route. Dimness stays a browser preference. A purchased assembly draws at its routed path with its library length beside it, and a core design rule warns, silenceable per segment, when the path is longer than the fixed length, since the cable cannot reach; a shorter path is fine. Reference photos beside the 3D view wait until a session against the robot shows the need. The decision was made on the ticket [What does the 3D view own, and what does it save?](https://github.com/alexchunlin/harnessy/issues/37).

## Considered options

- Keeping the write button, so 3D owns the length only when asked. Rejected: two numbers disagree between writes, a distance typed in the topology inspector loses on the next write, and undo of a write was a special case that dropped the tie points the write added.
- Saving the sketch, so every endpoint is placed as soon as the 3D view opens. Rejected: every length in the project would change the moment the view opened.
- Lengths frozen by refusing drags on single parts while locked. Rejected: positioning a harness would need a multi-select every time.
- Placement in `topologies/<top>.json` because it changes lengths. Rejected: tidying a 3D scene would rewrite the model file, which ADR 0001 split the folder to avoid.
- The reference model per topology in the `.3d.json` file. Rejected: it repeats the transform of one machine, and no topology has wanted a different model.
- A rotation on breakouts and splices. Rejected: nothing leaves them in a fixed direction; the strain relief is on the connector type.
- Writing the derived length into `length_mm` on every save as a cache. Rejected: it is the write button again, only hidden, and the file would carry a number nobody typed.
